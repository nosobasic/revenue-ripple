Implemented
1. RestrictedEvidenceStore uses rr_billing_private.lock_bound_user(uuid), reads the
   owner-managed binding without requiring UPDATE privilege, and resolves review
   charges through evidence before taking the same user lock. The default store
   remains available for existing fixtures. Missing user/binding returns unmatched
   review instead of acknowledging an unpersisted review outcome.
2. create_durable_app explicitly composes the restricted store, signed HTTP ingress,
   PostgreSQL ReceiptQueue and ReceiptWorker. No import/registration in server.py;
   no automatic environment discovery, schema setup, worker loop or startup.
3. Ingress authenticates raw bytes with Stripe's SDK and enforces mode/account/API
   contract before persisting only event id/type/scope/object id/charge reference.
   It omits raw payloads, customer details, metadata and signing secret. Commit
   precedes HTTP200. Invalid signature400, scope/event-identity conflict409, DB
   failure503. A semantically identical receipt dedupes by account+event id;
   conflicting event identity is rejected, never overwritten. Checkout ignored.
4. Worker uses canonical Stripe GET verification and trusted preexisting bindings.
   It cannot create bindings/catalog entries or change identity. Work claiming uses
   SKIP LOCKED, 120-second lease and unique token. Stale workers cannot acknowledge
   a replacement lease. Evidence and receipt transactions deliberately separate:
   crash after evidence commit replays safely as duplicate. Entitlement remains
   governed by immutable settled coverage and sticky manual review holds.
5. Retryable/provider/DB/unmatched-binding failures persist with exponential delay
   30,60,120,240,480,960,1920 seconds; attempt8 goes dead, as does an expired final
   lease. Event-level review rejection goes dead immediately. Refund/dispute before
   invoice settlement retries instead of disappearing. Receipt state counts are
   available through queue.counts(); no notification destination is configured.
